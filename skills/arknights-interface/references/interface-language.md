# 明日方舟风格的界面用语

适用于用户选择明日方舟 / PRTS 风格的页面与组件。用语规则与字体、颜色同属设计规范；实现前先确定目标产品的真实对象、动作和状态，再选择表达。

| 来源 | 官方用语证据 | 本项目提炼 |
| --- | --- | --- |
| [功能更新公告](https://ak.hypergryph.com/news/3078) | 情报处理室、模组陈列室、模组档案、干员模组总览 | 栏目采用明确对象加档案、总览、处理室等功能名；不同层级各有职责 |
| [活动与功能说明](https://ak.hypergryph.com/news/4942) | 解锁条件、开放时间、兑换说明、领取、收录 | 条件、时间、动作和结果清楚表达，风格不妨碍理解 |
| [公开招募刷新通知](https://ak.hypergryph.com/news/9601) | 区分未开始与已开始的招募状态，并交代刷新影响及处理时间 | 状态词应精确区分业务阶段；有影响的操作先说明适用对象和后果 |

下列词库和示例均为项目改写建议，不是官方按钮逐字摘录。PRTS 风格的“专业、克制、组织化”是依据上述资料的设计归纳，不是官方公布的写作准则。

## 三层语言

1. 栏目：简短、稳定的功能名，体现资料管理与行动组织。可按实际业务使用“终端总览、任务调度、设备档案、行动记录、资源管理”。同一对象全站使用同一名称。
2. 操作：动词加明确对象，通常 2–6 个汉字，清晰优先于长度。“查看档案、保存配置、开始采集、提交审核、导出记录”。不把保存统一改成归档，不把下载统一改成回传。
3. 状态：陈述已知事实，必要时补充原因和下一步。“等待分配、执行中、已完成、已取消、校验失败”。成功、失败、待处理、不可用必须区分，不用“异常”概括所有情况。

在语义匹配时优先采用有明日方舟辨识度的词：终端、档案、编组、部署、整备、调度、行动记录。例如“调阅档案”“编组管理”“整备中”“待命”；“待命”表示已就绪但尚未执行，“整备中”表示正在准备，“部署任务”仅用于确有部署或分配过程的任务。栏目、按钮和状态应贯穿同一套用语。

## 用语映射（原创建议）

| 场景 | 建议表达 | 使用条件 |
| --- | --- | --- |
| 总览 | 终端总览 | 工作台概览；具体业务仪表盘可保留原名称 |
| 资料详情 | 设备档案 / 组件档案 | 对象确实为设备或组件资料 |
| 队列与任务 | 任务调度 / 执行队列 | 存在分配、排队或执行流程 |
| 日志 | 行动记录 / 操作记录 | 按日志实际记录的对象选词 |
| 保存设置 | 保存配置 | 成功持久化后才显示“配置已保存” |
| 开始运行 | 开始采集 / 执行校准 | 保留实际动作，避免泛称“启动协议” |
| 停止任务 | 终止采集 | 确实终止而非暂停；可恢复则写“暂停采集” |
| 空结果 | 未检索到匹配记录。请调整筛选条件。 | 当前查询无结果，不代表系统完全没有资料 |
| 上传中 | 正在上传采集文件，3 / 12。 | 进度必须来自真实数据 |
| 网络失败 | 连接中断。请检查网络后重试。 | 已确认网络断开，不虚构中继节点故障 |
| 无权限 | 当前账号无权访问此档案。请联系管理员。 | 产品确有管理员流程 |
| 删除确认 | 删除这 3 条记录？删除后无法恢复。 | 实际不可恢复时才这样描述；按钮“保留记录 / 删除记录” |

## 句式与边界

- 栏目通常用 4–6 字名词短语；按钮写具体动作；说明用完整短句。字数是倾向，不能截断业务名称或重要后果。
- 优先普通、专业的中文。可用“档案、调度、编组、部署、校验、记录、补给”等词，但必须与资料管理、资源分配、分组或执行的实际语义对应。
- “协议”只用于规则或通信约定，“指令”只用于可执行命令，“归档”只用于进入归档状态；页面标题可以是“PRTS 视觉协议”，普通表单仍然是“保存配置”。
- 游戏专用词如干员、理智、寻访、源石不机械替换用户、额度、搜索、积分。除非目标业务本身是游戏资料工具，否则保留真实实体。
- “博士”称呼、阵营口号、角色对白和剧情隐喻只在用户明确要求的叙事区域使用，不放进通用按钮、错误、权限或删除确认里。
- 技术接口、日志字段和数据模型名保持兼容；只调整人读文案。一个实体不得在不同页面随机改称对象、节点或档案。
- 英文小标题只作必要分类或编号，中文负责完整解释。不以长串大写英文、斜杠或“协议已接入”等无意义状态营造气氛。
- 任何“已完成、已同步、已导出”须有相应结果证据；演示组件明确为示例。错误原因未知时写“请求未完成。请重试。”，不编造原因。

## 交付检查

逐项核对栏目、按钮、状态、空态、错误和高风险确认。给每种新业务实体确定唯一叫法，检查动词与实际行为、结果和恢复方式是否一致。说明哪些表达参考了官方命名方式，哪些属于本项目改写；不要宣称原创文案是游戏原文。
