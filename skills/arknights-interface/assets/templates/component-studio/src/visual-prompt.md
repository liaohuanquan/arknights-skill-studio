# PRTS 视觉协议 · 界面生成提示词

请依据当前已确认的 PRTS 页面，为目标产品实现明日方舟风格的工业终端界面。保留目标项目的框架、业务结构与交互，优先复用现有组件；需要引入组件基础时优先采用 shadcn/ui。将下面的视觉规则用于目标内容，而不是照搬示例数据或整套组件目录。

## 编写 UI 或组件前：先查阅样例模板
- 新建、修改页面或单个组件时，必须先参考本项目的 component-studio 样例模板，再开始实现。模板是布局、组件样式与交互的具体依据；不能只根据“明日方舟风格”或下面的文字概述自行发挥。
- 模板位于 arknights-interface Skill 目录下的 assets/templates/component-studio/；当前仓库中的完整相对路径为 skills/arknights-interface/assets/templates/component-studio/。在独立模板项目中，直接读取其 src/ 目录。
- 先在模板 src/main.js 的 22 组组件实例中找到与需求最接近的样例，再读取 src/style.css 中对应的选择器、共用变量与响应式规则；涉及粒子、鼠标或侧栏检索时，再查看 src/terminal-effects.js 或 src/terminal-navigation.js。
- 有可运行的模板或页面预览时，先查看对应区域的实际显示与交互。对照样例的字体分工、蓝底白字、边框、切角、间距和选中、禁用、焦点等状态，在目标项目已有组件体系中复用或封装。模板的原生 HTML/CSS 实现不要求目标项目更换框架。
- 没有直接对应的组件时，从最接近的样例和共用样式变量扩展，保持同一视觉语言；仅移植业务需要的结构与行为。交付时简要指出参考了哪个样例。若模板文件不可用，明确说明并请求提供模板，不声称已经参考过源码。

## 页面构成
- 整体采用黑、炭灰、冷白的高对比层次。桌面使用窄侧栏、104px 固定顶栏和独立滚动的内容区；内容区默认内边距为上 40px、左右 48px、下 72px。
- 首页由冷白主视觉区、黄色细线与节点、深色状态面板组成。当前示例主标题为“PRTS 视觉协议”，随后展示视觉参数、字体样张、协议条目、组件档案和提示词。
- 组件目录采用连续的横向文档行：左侧编号与名称，右侧展示可操作的实例；桌面标签列为 280px，1050px 及以下为 220px，720px 及以下改为上下排列。
- 只选用业务需要的按钮、状态、表单、表格、反馈、导航、指令队列和任务配给等组件。状态、进度和结果应来自实际数据；示例数值须明确是示例。

## 侧栏与响应式
- 桌面侧栏宽 152px；721–1050px 屏幕宽度下为 144px。侧栏、顶栏、主内容和滚动区共用同一个宽度变量。
- 侧栏使用半透明炭灰底和一条细右边线；文字居中，不添加大品牌块、桌面图标、独立菜单边框或选中底色。
- 导航项高 64px，项间距 8px，四项组成约 280px 高的紧凑分组，不随屏幕高度均分拉开。检索框高 48px，距导航组 18px。
- 侧栏上内边距为 clamp(56px, 10vh, 120px)，左右 12px，下方 32px；短屏允许缩小上下留白。筛选结果行高 56px，支持 Escape 清空和无匹配提示。
- 720px 及以下切换为 66px 高的底部四栏导航，保留图标和选中下划线，顶栏高 76px，正文为底栏预留空间。保持滚轮、触摸与键盘导航可用。

## 字体分工
- 中文页面、章节与组件标题使用 Noto Serif SC，700 或 900；中文按钮、正文和说明使用 Noto Sans SC，400 或 700。
- 数字、日期、时间、百分比、编号中的数字使用 Bender，分别提供 400 与 700 字体文件，不把普通中文或英文全部替换成数字字体。
- 侧栏英文使用 Bender，中文使用 PingFang SC、Microsoft YaHei 等系统无衬线字体。标签与检索文字均为 16px，全部保持 400，当前项也不加粗。
- 其他英文叙事与标签使用 Times New Roman；代码和提示词使用 SF Mono、Menlo 等等宽字体。

## 三档字号（优先于旧样例）
- 全站只使用三档字号：说明与辅助标签 12px（--text-sm: .75rem）、正文/按钮/输入框/导航/表格/代码 16px（--text-md: 1rem）、页面与章节标题/重点数字 24px（--text-lg: 1.5rem）。以浏览器默认 16px 根字号为基准，保留用户缩放。
- 所有 font-size 和 font 简写的字号统一引用这三个变量；禁止局部新增字号、连续 clamp/vw 字号、用 transform: scale 缩放文字，以及为 small/sup/sub 引入第四档。
- 桌面与手机共用三档，靠换行、间距、字重与颜色区分层级，不靠缩小字号塞内容。字号不能随选中、Hover 或加载状态变化。
- 当前模板已统一三档字号；历史截图可能保留旧字号。参考其他旧样例时，必须映射到这三档，不沿用超大 Hero 字和过小注释。

## 滚动条与滚动行为
- 主页面和独立 workspace 隐藏滚动条外观：Firefox 使用 scrollbar-width: none，WebKit 使用 ::-webkit-scrollbar { display: none; }；内容容器保留 overflow: auto，不用 overflow: hidden 禁止滚动。
- 侧栏内容溢出时保留细滚动条（scrollbar-width: thin）；代码、长提示词等局部滚动区沿用细条，避免粗大装饰轨道。移动端保留原生触摸滚动。
- 滚轮、触控板、触摸与键盘均可到达所有内容。需独立键盘滚动的区域设置 tabindex="0"、可访问名称和可见焦点；横向表格溢出仍能滚动，不拦截 wheel 事件或嵌套滚动制造卡死。

## 颜色、几何与状态
- 信号蓝统一为 #22bbff。按钮、开关、复选框、单选框、进度条、滑块与选中标记共用同一变量，浅色面板上的控件也使用这一亮蓝。
- 所有蓝底按钮及选中项使用白字。#006b8c 只用于浅底蓝色正文，不能拿来替换控件背景。
- 黄色 #ffd200 表示活动、配给、优先事项与主视觉细线；橙色 #dc6900 表示更新；红色表示危险或失败；绿色表示成功。用文字或形状补充颜色语义。
- 使用矩形、硬边、细边框、少量切角，默认圆角 0–2px。阴影向下柔和扩散，例如 0 14px 18px -9px rgba(0,0,0,.72)。
- 按钮 Hover 不改变背景、文字、阴影或位置，蓝色不能变浅；保留选中、按下、禁用和清楚的键盘焦点状态。鼠标圆环的悬停反馈单独处理。
- 不使用全屏网格、蓝紫渐变、大圆角玻璃卡片或密集霓虹描边。

## 背景粒子
- 使用低对比几何背景与淡斜纹。白色粒子位于内容后方，不拦截点击；优先复用模板的 terminal-effects.js。
- 初始数量为 floor((视口宽 + 视口高) / 38)，1920×1080 下为 78 颗。窗口缩放更新画布尺寸，保留已有粒子。
- 每个 requestAnimationFrame 向左移动 1–2px、向上移动 0.01–1.01px；每颗粒子独立随机，不改成按秒计时。
- 横向半径随机为 0.5–2px，纵向半径为横向的 0.3–1.3 倍；白色光晕模糊 0–3px，横纵偏移各 -1–1px，形成不同大小与虚实层次。
- 每帧清除每颗粒子旧位置的 12×12px 区域。越界后从右边缘随机高度重新进入；隐藏标签页时暂停，减少动态效果时冻结。

## 鼠标与动效
- 复用模板 src/terminal.css 的 --terminal-pointer 白色 6px PNG 小指针，热点为 (3, 3)，保留 default 回退；同时读取 src/terminal-effects.js，不能只引用 CSS 而遗漏圆环逻辑。在精细鼠标设备且宽度大于 768px 时，叠加 36px 圆环、1px #ccc 边框；不使用反差混合模式。
- 圆环使用 fixed 层与 clientX/clientY 对齐；移出窗口、失焦、标签页隐藏或键盘 Tab 导航时隐藏，卸载时清理事件、定时器与动画帧。触屏和粗指针设备不显示跟随圆环。
- 圆环按 min(0.025 × 帧间隔毫秒数, 1) 插值跟随。悬停可操作控件时收至 24px，填充约 53% 白色，大小与填充过渡为 300ms。
- 点击后显示 80px、4px 边框的波纹，从 scale(0) 扩展到 scale(1) 并淡出，持续 500ms，曲线为 cubic-bezier(.22, .61, .21, 1)。波纹未结束时忽略重复触发。
- 圆环和波纹尺寸使用 content-box。控件状态过渡 160ms，内容进入 320ms、位移不超过 8px，进度进入可用 640ms。
- prefers-reduced-motion 下移除圆环与波纹、关闭动画与平滑滚动；装饰层设置 pointer-events: none 并对辅助技术隐藏。

## PRTS 文案
- 编写页面与组件用语前，读取 Skill 的 references/interface-language.md。官方“情报处理室、模组档案”等命名体现功能与对象；以下表达为本项目的风格提炼，不冒充官方原文。
- 栏目用简短稳定的功能名，如“终端总览、设备档案、任务调度、操作记录”；按钮写具体动词与对象，如“查看档案、保存配置、开始采集、提交审核”。同一实体全站保持同一名称。
- 状态陈述事实并按需给出下一步：“等待分配、执行中、已完成、校验失败”；空态可写“未检索到匹配记录。请调整筛选条件。”；确认删除时交代对象数量、后果及是否可恢复。
- 用语专业、克制，清楚表达条件、时间与结果。“协议”只用于规则或通信约定，“归档”只用于归档动作，不把所有保存、下载、运行操作改成“写入协议、回传、执行指令”。
- 不把用户、额度、搜索、积分机械改称干员、理智、寻访、源石；保留目标业务实体。角色对白、博士称呼和剧情隐喻不进入普通按钮、权限或错误提示。
- “已同步、已导出、已归档”等结果必须来自成功行为，演示状态明确标为示例；原因未知时写“请求未完成。请重试。”，不虚构链路或设备故障。
